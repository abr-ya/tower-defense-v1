# Agent Working Agreement

Read `docs/PROJECT.md`, `docs/ARCHITECTURE.md`, and `docs/BACKLOG.md` before proposing or implementing changes.

## Language and naming

- Write repository artifacts in English, including OpenSpec documents, documentation, code comments, and UI text, unless the user explicitly requests another language. Conversation may use Russian.
- Name branches `<type>-<number>-<short-kebab-slug>`, for example `feature-130-admin-table-default-sort-hint`.
- Use conventional commit messages with a scope, for example `feat(admin): Add table sort status` and `docs(openspec): Archive feature-130 sort status`.

## Delivery workflow

1. Use OpenSpec (OPSX) for every implementation feature. Start from one backlog item, create/review its change artifacts, then implement only approved scope.
2. Commit each approved OpenSpec planning package before implementation. Commit implementation in one or more reviewable stages. After implementation, sync and archive the OpenSpec change, then commit the resulting specifications and backlog updates separately. Before every commit, propose the conventional commit message and wait for the user's explicit approval.
3. Keep `BACKLOG.md` current. Do not mark an item DONE before tests, smoke check, and archive.
4. Never couple simulation rules to Phaser, React, browser APIs or persistence.
5. Prefer small, typed, testable modules and data-driven content; do not invent a general-purpose engine.
6. Respect mouse and touch inputs, logical world coordinates, and browser-first operation.
7. For builds, automated checks, and manual smoke tests, provide the exact commands and scenarios for the user to run. Review the user-provided results before treating the checks as passed.
8. Report changed files, commands to run, user-provided test results, risks, and next backlog item after implementation.
9. Ask before adding major dependencies, servers, authentication, or changing platform strategy.
10. For OpenSpec commands, use the syntax generated by `openspec init` for the selected OpenCode integration.
